zinet

The shared graph IR core: a graph.yaml format with a validator and transforms.

Like LLVM IR for the ZiNets ecosystem: front-ends emit it, back-ends consume it.

https://github.com/digital-duck/zinet
zinet is a small Python package. It holds the graph format and the code that checks and transforms it, so the other apps do not each keep a copy.

    The problem: duplicated graph code

    • Graph-Code, ConceptBook, GraphLang and work-graph each carried their own copies of graph algorithms.
    • Drawing code was copied too (GraphLang and work-graph).
    • YAML handling was copied as well, including comment-preserving round trips in work-graph.
    • ConceptBook is named as the closest relative and the biggest source of duplicated graph code.

    Cost of copies

    The copies differ in small ways.
    The differences are frozen in characterization tests.
    The ecosystem has several graph-first apps. Each grew its own learning-path, ordering, drawing and YAML code. zinet pulls that into one package.

    The idea: one graph IR

    • Front-ends emit graph.yaml.
    • Back-ends consume it.
    • The validator and transforms live once, in a shared package.
    • zinet is small and domain-free; domain rules (for example solver bounds) belong in the back-end.
    • It persists a graph in plain YAML and does not run anything.

    Shared here

    ✔ format and schema
    ✔ validate, diff, slice
    ✔ render and prettify
    ✔ algorithms and drawing
    The comparison is with compilers: one intermediate form, many front-ends and back-ends. Only the core checks are in zinet.

    Origin: characters as decomposition graphs

    • ZiNets began with Chinese characters: each decomposes into radicals, strokes and abstract primitives.
    • That decomposition is a directed acyclic graph.
    • The same structure turned out to fit knowledge, code, computation and optimization.
    • The instinct is a physicist's: protons to quarks to fields.

    Every complex thing

    primitives
    compositions
    capstone applications
    This is the history from the graph vision notes. The character explorer was the first user of the graph, and the data structure generalised.

    Three layers: primitives, concepts, applications

    primitives:            # leaves: must not have deps
  - id: x_units
    meta: {type: variable}
concepts:              # composed from the layer below
  - id: capacity_constraint
    deps: [x_units, max_units]
    edge_types: {max_units: constraint}
applications:          # capstones: nothing depends on these
  - id: minimize_cost
    deps: [capacity_constraint]
    • Primitives are leaves and must have no deps.
    • Nothing may depend on an application.
    The layer is the key a node is written under, not a field of the node. An empty document is valid.

    Nodes, deps and edge types

    • Node fields: id, label, deps, edge_types, meta.
    • deps are incoming edges; ids are unique across imports.
    • meta is opaque: the core never reads it.
    • Unknown keys are rejected, so a typo such as primitves: fails at load time.

    Five edge types

    depends_on (default)
    data_flow
    prerequisite
    constraint
    inheritance
    Edge types affect rendering and documentation only. Validation treats all edges the same.

    Validation checks

    CodeSeverityMeaning
    duplicate_iderrorid defined more than once
    unknown_deperrordep names a missing id
    primitive_has_deps / layer_violationerrora leaf with deps / a dependency on an application
    cycleerrornot a DAG
    orphanwarningno deps and no dependents
    not_reducible, disconnectedoptionalon with --strict
    The two optional checks are off by default, so a graph that is valid today stays valid. not_reducible is an error and disconnected is a warning.

    Demo: validating a broken graph

    $ zinet validate broken.yaml
broken.yaml: error: primitive_has_deps [a]: ...
broken.yaml: error: unknown_dep [c]: depends on
  undefined id 'ghost'
broken.yaml: error: cycle: dependency cycle among: c, d
broken.yaml: warning: orphan [app]: not connected to
  any other node
    • Exit code 1 on errors; warnings are printed but do not fail.
    • Exit code 2 on a usage or load failure.
    Demo write the broken.yaml from the tutorial and run zinet validate broken.yaml.
    The graph has a primitive with a dependency, an unknown id, a cycle and an isolated application. Each shows up as one line.

    One command, seven subcommands. Exit code 2 always means a usage, load or render error.

    Diff and slice

    zinet diff old.yaml new.yaml
zinet slice graph.yaml target_id -o part.yaml
    • diff prints + id for added, - id for removed and ~ id.field: old -> new for changed nodes.
    • diff exits 1 when the graphs differ, 0 when they do not.
    • slice gives the target plus its prerequisite closure.
    • Without -o, the slice is written to stdout.
    Slice is useful for pulling out just what one target needs. Diff works in CI because of the exit code.

    Rendering and the interactive page

    • Formats: svg, png, pdf, mermaid, html, ascii.
    • html, mermaid and ascii need nothing installed.
    • svg, png, pdf need Graphviz dot; png and pdf need -o.
    • Cytoscape.js is bundled, so the page works offline: search, zoom, click a node.
    zinet render graph.yaml \
  --format html -o graph.html
    The default format is svg to stdout. The html page is a single file.

    Drawing any networkx graph with zinet.vis

    • Engines: cytoscape (default), graphviz, mermaid, ascii; pyvis and graphify as extras.
    • A Style reads your attribute names, so no app has to rename anything.
    • select trims a big graph: filters, hidden kinds, hub edges, a node cap.
    • GraphLang and work-graph output is checked against golden files.
    from zinet.vis import render, select
render(G, "graph.html")
sub, note = select(G, node="app",
                   hops=2)
    GraphLang and work-graph used to carry their own drawing code. Now they use these engines.

    Shared graph algorithms

    import zinet
G = zinet.to_networkx(zinet.load_graph("graph.yaml"))
zinet.learning_path(G, "app", known=["a"])
zinet.productivity_order(G)
zinet.reducible(G)
zinet.build_order(G)
zinet.gap(G, "app", ["a"])
zinet.ensure_acyclic(G)   # raises CycleError
    • Plain networkx.DiGraph; options reproduce the older copies. Defaults follow graph-code.
    • A missing node raises UnknownNodeError.
    Graph-code and ConceptBook had their own versions. The options select which behaviour you get, and tests freeze what each copy did.

    Comments survive: prettify and convert

    • prettify --write keeps YAML comments, or refuses to rewrite the file.
    • prettify without --write shows a diff and exits 1 if the file would change.
    • convert goes between YAML and JSON.
    • JSON has no comments, so they go into SQLite at ~/.zinet/comments.db.
    • A comment whose node was removed is written as # [orphaned from <id>].

    Store location

    ~/.zinet/comments.db
    $ZINET_HOME
    --store PATH
    This is the approach work-graph uses for its layer files, now shared code in zinet.roundtrip.

    Two graph formats, one family

    • zinet: a static dependency graph.
    • GraphLang *.graph.yaml: an executable workflow with ports, control and data edges, loops.
    • The file name is only a convention, so each tool tells them apart by content.
    • Given the other kind, a tool names the file's kind and the right command instead of a schema error.

    By content

    workflow: + nodes: + edges: is GraphLang
    primitives:, concepts:, applications: is zinet
    Folding GraphLang into zinet would force its model on the other apps, so the two stay separate and share drawing code.

    Python API and install

    pip install zinet

from zinet import (load_graph, validate,
                   slice_to, dump_graph)
graph = load_graph("solver_pipeline.yaml")
for issue in validate(graph):
    print(issue)
prereqs = slice_to(graph, "minimize_cost")
    • Core dependencies: networkx, pydantic, pyyaml. Python 3.10 or newer.
    • load_graph resolves imports but does not validate.
    Version 0.2.1, Alpha status. For development, install from source with uv and the dev extra.

    How it is tested

    • A pytest suite, with one fixture graph per domain in tests/fixtures.
    • A test fails if the committed schemas/graph.schema.json is out of date.
    • Characterization tests in tests/characterization freeze what the old copies did.
    • Where the copies disagree is written in divergences.md.
    • The interactive page's JavaScript is checked with node and headless Chrome, skipped when missing.
    The golden files let the shared code replace the copies without changing their output.

    Not done yet

    • No domain-specific JSON Schema overlays (solver, spl, cba).
    • No graph.html explorer in this package; it belongs to cba.
    • spl3 integration is the next step: SPL scripts compiling to GraphIR.
    • The ConceptBook / graph-code dialect (composed_of, needs) is not read yet.
    • Status is Alpha.
    The algorithms and drawing already work on any networkx graph, so the dialect gap affects loading files, not the shared code.
